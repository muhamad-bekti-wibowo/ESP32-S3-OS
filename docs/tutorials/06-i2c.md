# 6. I2C Register-Level

Runtime ini **tidak punya driver sensor spesifik** (tidak ada node
"LCD1602" atau "BMP280"). Hanya dua primitive generik:

- `i2c_read_reg` — baca register.
- `i2c_write_reg` — tulis register.

Sensor/modul apa pun dikomposisikan dari dua primitive ini di level
graph JSON, sesuai datasheet-nya masing-masing. Tidak ada `hw_mode`
untuk I2C (selalu bus fisik sungguhan — tidak ada mode simulasi yang
masuk akal untuk device dengan alamat I2C nyata).

Bus I2C default: **SDA = GPIO8, SCL = GPIO9**. Timeout dibatasi 8ms —
kalau device I2C tidak merespons (NACK/salah alamat), scan cycle tidak
akan macet, cuma `outputs[1]` (`error`) jadi `true`.

## Params

| `type` | `params` | Output |
|---|---|---|
| `i2c_read_reg` | `bus`, `address` (7-bit), `register`, `length` (1-8) | `outputs[0]` = raw bytes, `outputs[1]` = error (bool) |
| `i2c_write_reg` | `bus`, `address`, `register`, `data` (array 1-7 byte) | `outputs[0]` = sukses (bool) |

## Contoh: LCD 16x2 dengan backpack PCF8574 (alamat 0x27)

PCF8574 mengontrol LCD lewat 8-bit port paralel (bukan protokol
register LCD langsung) — datasheet backpack biasanya memetakan bit
tertentu ke pin `RS`/`RW`/`E`/`D4-D7`/backlight. Detail penuh protokol
inisialisasi LCD di luar scope tutorial ini (banyak referensi online
untuk "PCF8574 LCD init sequence"); di sini fokus ke cara memakai node
`i2c_write_reg` untuk mengirim byte apa pun ke alamat itu.

1. Tambah node `i2c_write_reg`.
2. Isi Properties: `bus = 0`, `address = 39` (desimal dari `0x27`),
   `register = 0` (PCF8574 tidak punya konsep register terpisah —
   biasanya `register` diisi `0` dan data langsung ditulis ke port),
   `data` = isi field CSV byte, misal `16, 32` (dua byte contoh).
3. Save. Cek response `GET /api/program`, lihat `outputs[0]` node ini
   — `true` berarti device menerima ACK dari alamat `0x27` (sukses),
   `false`/error berarti tidak ada device di alamat itu atau salurannya
   bermasalah.

## Membaca status (cek device ada atau tidak)

```
i2c_read_reg(bus=0, address=39, register=0, length=1)
```

Cek `outputs[1]` (`error`) di response `GET /api/program`:
- `false` → device merespons di alamat itu.
- `true` → tidak ada device di alamat itu / bus bermasalah / timeout.

Ini cara paling sederhana untuk memverifikasi wiring I2C benar sebelum
melangkah ke command sequence yang lebih rumit (seperti init LCD).

## Live monitor untuk debug I2C

`outputs[0]`/`outputs[1]` setiap node I2C selalu muncul di response
`GET /api/program` (field `outputs`, ditambahkan khusus untuk kebutuhan
monitoring seperti ini) — polling endpoint itu berulang untuk melihat
hasil komunikasi I2C berubah real-time, tanpa perlu serial monitor.
